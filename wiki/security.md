# 安全与故障排查

## 访问控制

首次密码只能在运行程序的电脑（回环地址）上设置，至少 6 位；登录后发 30 天签名 Cookie，同一来源连续失败 5 次触发锁定（1 分钟起翻倍，最长 15 分钟）。默认监听所有网卡（`0.0.0.0:8090`），局域网设备可访问管理页；仅本机使用时将 `listen` 改为 `127.0.0.1:8090` 并重启。公开互联网部署应增加 TLS、网络访问控制与可靠身份管理。

配置文件包含机器人地址、模型密钥、SNMP 团体名和认证信息，应限制文件权限并保存在私有备份中。不要开启不需要的 MCP 写入能力；运行第三方插件前审查其代码和权限。

## 常见问题

| 现象 | 排查顺序 |
|---|---|
| 网页打不开 | 程序进程、端口占用、listen、防火墙、日志 |
| Ping 不通但设备能用 | 设备是否禁 ICMP，尝试 TCPing，核对 IP 与 ARP |
| MAC 或新设备缺失 | 本地网络权限、网段范围、ARP 可见性 |
| SNMP 失败 | 管理 IP、UDP 161、只读团体名、ACL、SNMP v2c |
| 告警未送达 | 渠道启用、设备告警开关、维护窗口、代理、告警发送结果 |
| AI 连接失败 | 协议、URL、模型名、Key、代理和服务余额 |
| SSH 指纹变化 | 先核实设备身份，再清理旧的信任记录 |

## 忘记密码

停止程序，私下编辑 `config.yaml`，删除 `auth` 下 `password_hash` 和 `password`，重启后在运行程序的电脑上重新设置。此操作需要本机文件访问权限。

## 报告漏洞

遵循仓库 [SECURITY.md](../SECURITY.md)；不要在公开 Issue 粘贴密钥、真实拓扑或可直接利用的漏洞细节。已经暴露的密钥必须到服务端撤销或轮换；删除 Git 历史不能代替撤销。
